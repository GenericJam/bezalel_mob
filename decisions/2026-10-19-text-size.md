# Text size: Mob's theme text_scale, chrome capped
- Date: 2026-10-19
- Status: accepted

## Context
Kevin (2026-10-19): "The text size needs to be in settings so users can
choose how big to make the text." Every size in the app and in
mob_bezalel is a number from the design (`text_size={15}`), about 300 of
them. Mob's theme `type_scale` scales only the size tokens (`:base`,
`:xl`) and leaves numbers alone on purpose (mob_mishka relies on it), so
it couldn't carry a user preference here. A walk over each screen's
render output would have missed nothing today but needed every new screen
to remember it.

## Decision
- **Mob 0.9.23's `text_scale`** (GenericJam/mob#216, PR #217): a theme
  field the renderer multiplies into every node's `text_size` / `font_size`,
  number or token. `Bezalel.Settings.theme/1` is what every
  `Mob.Theme.set/1` here passes: `{module, text_scale: text_scale()}`, the
  `{module, overrides}` form so `MobBezalel.System` keeps it across an OS
  light/dark flip (AppScreen, Settings, the design gallery).
- **Five steps**, `Settings.text_size/0` in `Mob.State`
  (`:bezalel_text_size`): small 0.85, default 1.0, large 1.15, larger 1.3,
  largest 1.5. Settings → Appearance → Text size: five "A"s drawn at the
  sizes they choose (divided by the current scale so the row stays put),
  the choice's name, and Exodus 31:2 at the chosen size.
- **On top of the phone's own font scale**, not instead of it: Android
  sizes are `sp`; on iOS the theme's custom fonts (`Font.custom`) follow
  Dynamic Type. Text fields on iOS are fixed points, so only the setting
  moves them there.
- **Chrome with fixed room grows less** (mob_bezalel's
  `MobBezalel.capped_size/2`): the top bar's title and buttons and the
  segmented controls up to 1.15×, the tab bar's labels not at all (five
  labels already fill a 360 pt phone; the icons carry the meaning), the
  Materials tile's name up to 1.15×. The chip label's cut follows the
  scale. The Markdown views' `text_size` is a top-level prop of the native
  view, so the renderer scales it like any text.

## Consequences
- New text needs nothing: a number or a token follows the setting. Text in
  a fixed-size box or a `max_lines: 1` row should be checked at Largest
  and, if it can't grow, use `MobBezalel.capped_size/2`.
- A Canvas `text` op's `size` (drawing geometry) and sizes nested in a
  plugin's style map don't follow it (Mob's docs).
